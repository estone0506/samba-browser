# 외부 프로그램 원가·배송비 기입(export) 설계

- 작성일: 2026-09-28
- 상태: 설계 승인(사용자), 구현 계획 작성 전
- 관련: `2026-09-22-langgraph-harness-design.md`, `2026-09-23-all-orders-expansion-design.md`

## 1. 목적

삼바브라우저 하네스가 처리한 주문을 외부 프로그램 두 곳에 반영한다.

- 플레이오토 EMP (설치형, `emp.exe`): 주문 목록의 **원가** · **배송비** 열에 값을 기입한다.
- 샵마인 (설치형, `shopmine.exe`): 값 기입이 아니라 **작업상태를 '완료됨'으로 일괄 지정**한다
  (사용자 2026-09-28 확정 — §6.1).

EMP 기입 항목은 원가·배송비 두 개뿐이다. 소싱주문번호·계정·메모 등은 범위 밖이다.

## 2. 확인된 사실(2026-09-28 실기 탐색, 읽기 전용)

| 항목 | EMP 1.1.0.458 | 샵마인 |
|---|---|---|
| 실행 권한 | 관리자 권한 | 일반 권한 |
| 주문 그리드 | 자체 그리기 컨트롤. UIA·win32 로 셀이 읽히지 않는다 | 표준 `DataGridView`. UIA 로 셀 접근 가능 |
| 열 | 수량 · 원가 · 공급가 · 판매가 · 배송비 순으로 표시됨 | 주문 화면 미확인(탐색 시 `쇼핑몰 연결` 대화상자가 떠 있었다) |
| API | 삼바웨이브 `PlayAutoClient` 기준 주문 조회·송장 전송만 있다. 원가 수정 없음 | 없음 |

EMP 가 관리자 권한으로 돌기 때문에 일반 권한 프로세스(삼바브라우저 Electron, 하네스)는
EMP 에 키·마우스 입력을 보낼 수 없다(Windows UIPI). 따라서 폰 도구처럼 Electron main 에
도구를 두는 방식은 EMP 에 쓸 수 없다.

## 3. 구조

```
하네스(일반 권한)                         입력 작업자(관리자 권한)
buy → pay → record → verify → export
                              │ 요청 적재             ┌→ EMP 어댑터
                              └→ 큐(SQLite) ←─ 폴링 ──┤
                                 결과 되읽기           └→ 샵마인 어댑터
```

| 구성 요소 | 책임 | 의존 |
|---|---|---|
| 큐 | 기입 요청과 결과를 보관한다. 하네스와 작업자의 유일한 접점 | SQLite 파일 |
| `export` 단계 | 대상 프로그램을 정하고 요청을 적재한 뒤 결과를 기다린다 | 큐, 라우팅 설정 |
| 라우팅 | 판매처 → 대상 프로그램 | 설정 파일 |
| 입력 작업자 | 큐에서 한 건씩 꺼내 어댑터를 호출한다. 한 번에 1건만 처리한다 | 큐, 어댑터 |
| 어댑터 | 프로그램 1개의 화면을 조작한다 | pywinauto |

## 4. 하네스 `export` 단계

- 위치: `verify` 뒤. 검증을 통과한 값만 내보낸다.
- 입력: 주문번호, 판매처, 원가, 배송비.
  - 원가는 삼바웨이브에 기록한 매입금액(`cost`, 하네스 기대값 `real_price`)과 같은 값이다.
  - 배송비는 `shipping_fee` 다.
- 동작: 라우팅 → 큐 적재 → 결과 대기(제한 시간) → 결과 반환.
- `dry_run`: 적재하지 않고 계획(대상·값)만 돌려준다.
- 사람 승인 게이트는 두지 않는다(외부 결제가 아니다).

### 4.1 라우팅

설정 파일에 판매처 표식 목록을 둔다. 판매처 문자열에 표식이 들어 있으면 그 대상이다.

| 대상 | 판매처 |
|---|---|
| EMP | GS이숍 · 롯데아이몰 · 현대H몰 · KT알파쇼핑 |
| 제외 | 포이즌 · 크림 |
| 샵마인 | 위에 해당하지 않는 나머지 |

- 주문 한 건은 한 곳에만 기입한다.
- 제외 대상은 기입 없이 성공으로 끝낸다(사유를 근거에 남긴다).
- 목록은 코드가 아니라 설정 파일에서 고친다.

## 5. 큐

SQLite 테이블 1개.

| 열 | 뜻 |
|---|---|
| `id` | 요청 id |
| `order_no` | 주문번호 |
| `target` | `emp` · `shopmine` |
| `cost`, `shipping_fee` | 기입할 값 |
| `status` | `pending` · `running` · `done` · `failed` |
| `fail_reason`, `detail` | 실패 사유와 설명 |
| `attempts` | 시도 횟수 |
| `created_at`, `updated_at` | 시각 |

- `(order_no, target)` 은 유일하다. 같은 요청이 다시 오면 기존 행을 돌려준다(중복 기입 방지).
- `done` 인 요청과 값이 다른 재요청은 거절한다(덮어쓰기는 사람이 한다).
- 개인정보는 담지 않는다.

## 6. 어댑터

공통 인터페이스:

```
find(order_no)            → 행을 1건으로 특정한다
read(order_no)            → 현재 원가·배송비
write(order_no, cost, shipping_fee)
```

| | EMP |
|---|---|
| 행 찾기 | 검색창에 주문번호 입력 → 결과 건수 1 확인 |
| 입력 | 원가·배송비 셀 입력 → `저장` |
| 되읽기 | 재검색 후 화면 값 확인 |
| 열 위치 | 헤더 글자로 찾는다 |

열 위치는 좌표로 고정하지 않는다. 사용자가 열 순서나 창 크기를 바꿔도 동작해야 한다.

### 6.0 EMP — 그리드 칸에 직접 입력(실기 2026-09-28)

- EMP 는 관리자 권한으로 돈다. 드라이버도 관리자 권한 프로세스에서 불러야 그리드가 읽히고 입력된다.
- 주문 그리드는 C1 FlexGrid(`grid`). 행 요소의 legacy Value 가 82열 값을 탭으로 이은 문자열이고
  첫 행이 열 이름이다 → `주문번호`·`원가`·`배송비` 를 이름으로 읽는다.
- 입력은 **그리드 창 핸들에 메시지를 직접 보낸다**. 실제 마우스·전역 키 입력은 쓰지 않는다 —
  다른 창이 앞에 있으면 글자가 그 창으로 샌다(실기: 채팅창에 입력됨).
  1. 칸(`wprice1` = 원가, `deliv_price` = 배송비)에 더블클릭 메시지 → 그 칸이 포커스를 받는다.
  2. 숫자 한 글자를 보내면 편집 상자(Edit)가 열린다.
  3. 편집 상자에 값을 통째로 넣고(WM_SETTEXT) 되읽어 같은지 확인한다.
     글자를 하나씩 보내면 기존 값과 섞인다(57131 → 507131).
  4. Enter → 행 값이 넣은 값과 같은지 확인한다.
- UIA ValuePattern.SetValue 는 반영되지 않는다(예외 없이 무시된다).
- `저장` 은 변경이 있을 때만 켜진다. 누르면 `저장완료` 안내창이 뜬다 → `확인`.
- `새로고침` 때 저장 안 된 편집이 있으면 `저장하시겠습니까?` 를 묻는다 → 우리 값은 이미 저장했으므로
  `아니요`(뜻하지 않은 편집을 버린다).
- 되읽기는 새로고침 뒤 그리드 값으로 한다(서버에 저장된 값).
- 칸이 화면 밖(가로 스크롤·행 스크롤)이면 입력하지 않고 물러난다(`blocked`, 재시도).
- 실기: 3건 기입(57,131/2,300 · 59,843/2,300 · 64,500/0), 1건은 배송비 5,000 이 이미 있어 덮어쓰지
  않음(`value_conflict`), 1건은 같은 값이라 입력 없이 완료. 건당 18~24초.

### 6.1 샵마인 — 하네스가 이행한 주문만 작업상태 '완료됨'(사용자 2026-09-28)

샵마인은 주문별 값 기입이 없다. 하네스가 주문을 처리한 직후, 통합주문관리 화면에서
`미지정 · 엑셀생성안됨` 필터에 걸린 주문 중 **하네스가 이행한 주문만** 완료됨으로 바꾼다.
(처음에는 "필터 결과 전부"였으나 같은 날 사용자가 "이행한 것만"으로 바꿨다.)

절차(모두 UI 자동화, 통합주문관리 탭):
1. 상단 상태 콤보(`ComboBoxProcessStatus`)를 `(정상전체)` 로 두고 `수집하기(F5)`. 기간은 화면 기본값.
2. 수집이 끝날 때까지 기다린다(`PanelLoading` 이 사라지고 수집 버튼이 다시 눌린다).
3. 주문필터 툴바에서 작업상태 = `미지정`, 엑셀생성여부 = `엑셀생성안됨`.
   콤보는 automation id 가 숫자(불안정)라 **항목 목록으로 구분**한다.
4. 필터에 걸린 행의 `주문번호` 칸 값을 읽어, 넘겨받은 주문번호와 맞는 행을 찾는다.
   대조 규칙: 정확히 같음 / 하네스 번호의 `:` 앞부분이 같음(SSG) / 공백 토큰 중 하나가 같음(GS이숍).
5. 헤더 전체 선택을 풀고 맞는 행만 체크한다(체크 칸은 다음 칸을 눌러 확정한 뒤 읽는다).
   대상이 아닌 행에 남은 체크는 푼다.
6. `작업상태지정` → `완료됨`. 확인 창의 "선택한 N개" 가 체크한 행 수와 같을 때만 `예` 를 누른다.
   뒤이어 뜨는 결과 안내창(`… 되었습니다`)은 닫는다.
7. 되읽기: 같은 필터에 처리한 주문번호가 남아 있으면 실패(`verify_mismatch`).

어댑터 규약(배치형): `complete_pending(order_nos) -> 처리한 주문번호 집합`. 작업자는 샵마인 요청
하나를 집고 그때 대기 중인 샵마인 요청의 주문번호를 모두 넘긴다. 처리된 주문의 요청은 성공으로
끝내고, 화면(필터)에 아직 없는 주문은 시간을 두고 다시 본다(횟수 초과 시 `not_found` 실패 → 알림).

큐의 `cost`·`shipping_fee` 는 샵마인 요청에서는 쓰지 않는다(값은 남겨 둔다).

화면 요소는 **보이는 자식 창 핸들**을 열거해 automation id 색인으로 찾는다 — 창 전체 UIA 검색은
주문 수백 행 × 56칸 때문에 한 번에 20초가 걸리고, 숨은 탭 페이지가 같은 id 를 갖는다.

실기(2026-09-28): SSG 주문 4건을 이 절차로 완료됨 처리했다(1건 + 3건). 수집 대기 40~60초를
빼면 전체 20초 안팎. 샵마인 자체 수집 오류(쿠팡 조회 오류)로 그 마켓 주문이 빠진 경우 그 주문은
"화면에 아직 없음" 으로 남아 다음에 다시 본다.

## 7. 안전 장치

1. 검색 결과가 1건이 아니면 입력하지 않는다.
2. 입력 직전에 선택된 행의 주문번호를 다시 확인한다. 다르면 중단한다.
3. 셀에 이미 값이 있고 기입할 값과 다르면 덮어쓰지 않는다 → `needs_human`.
   값이 같으면 입력 없이 성공으로 끝낸다.
4. 입력 뒤 되읽은 값이 다르면 실패(`verify_mismatch`)다. 재시도하지 않는다.
5. 사람이 그 창을 쓰는 중이면(최근 키·마우스 입력) 기다린다.
6. 인증·오류 대화상자가 떠 있으면 중단한다. 대화상자는 건드리지 않는다.
7. 작업자는 한 번에 1건만 처리한다(창이 하나다).

## 8. 실패 처리

외부 기입이 실패해도 주문은 완료 상태를 유지한다. 재결제·재기록은 없다.

| 실패 | 처리 |
|---|---|
| 창 없음 · 사용 중 · 시간 초과 | 큐에서 자동 재시도(횟수 제한) |
| 주문 없음 · 결과 여러 건 · 값 충돌 · 되읽기 불일치 | 재시도 없음. 슬랙 알림, 미기입으로 남긴다 |
| 작업자가 꺼져 있음 | 요청은 큐에 남는다. 작업자가 다시 뜨면 처리한다 |

`export` 단계가 제한 시간 안에 결과를 못 받으면 주문은 완료로 끝내고 "외부 기입 대기 중"
을 근거에 남긴다.

## 9. 테스트

- 단위: 큐(중복·상태 전이), 라우팅, `export` 단계(가짜 큐), 작업자(가짜 어댑터).
- 어댑터: 읽기 전용 시험(검색·행 특정·값 읽기)을 먼저 통과시킨다.
- 실기: 실제 주문 1건을 실시간으로 지켜보며 기입한다. 성공할 때까지 즉시 고친다.
- 기존 하네스 테스트와 `dry_run` 흐름은 그대로 통과해야 한다.

## 10. 구현 순서

1. 큐 + 라우팅 + `export` 단계(어댑터 없이 검증 가능)
2. 입력 작업자 + 샵마인 어댑터
3. EMP 어댑터(읽기 방법 확정 → 입력)
4. 작업 스케줄러 등록(최고 권한) + 실주문 1건 시험

## 11. 범위 밖

- EMP 원가·배송비 외 항목 기입
- 과거 주문 일괄 기입
- 마스터 엑셀 `샵마인` 시트 기입(`balju_fill.py` 가 계속 맡는다)
- EMP·샵마인 로그인·인증 자동화
