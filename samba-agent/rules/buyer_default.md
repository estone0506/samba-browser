# 구매 에이전트 — 공통 규칙

소싱처별 규칙 파일(`rules/buyer_<key>.md`)이 없으면 이 규칙으로 일한다.
사이트마다 다른 것은 저장 스크립트(`<key>_product_snapshot` · `<key>_set_shipping`)가 흡수한다.

## 1. 단계
1. 소싱 계정으로 로그인 확인 → 상품 페이지 열기 → 옵션·수량 선택
2. 계정별 쿠폰 비교 → 계정 확정
3. 배송지 결정·반영
4. 결제수단·카드 확정

## 2. 원가 규칙(스펙 §3)
- 원가 = (쿠폰·회원할인·카드 청구할인 적용, **적립금 사용 전**) − 확정 신규 적립
- 실구매가 = 결제액 + 사용 적립금 − 확정 신규 적립

## 3. 반드시 거절해야 하는 경우
- 옵션·사이즈가 없다(품절 표기 포함) → fail(out_of_stock)
- 마진이 기준 미만 → fail(margin)
- 지시받은 카드가 결제수단 목록에 없다 → fail(card_missing)
- 캡차·2단계 인증 화면 → needs_human(captcha)
- 같은 상품을 이미 산 흔적(소싱주문번호 존재) → fail(duplicate)
- 주문의 소싱 계정과 로그인된 계정이 다르다 → needs_human(permission_denied)

## 4. 쓰는 도구
등록부 `tools` 목록만. 결제창 진입·결제 버튼은 이 에이전트가 누르지 않는다(결제 에이전트 담당).

## 5. 개인정보
배송지(이름·전화·주소)는 입력하는 순간에만 쓰고 근거·기록에는 마스킹한 요약만 남긴다.

## 6. 판단마다 남길 근거(reason)
옵션 매칭 · 계정 선택 · 배송 방식 · 수단과 카드 — 네 가지는 한 문장씩 근거를 남긴다.
